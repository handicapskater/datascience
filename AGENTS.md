# Datascience notebook instructions

Read `../handicapskater-workspace/PROJECT_STATE.md` and the task-relevant
workspace contracts first. The evidence platform owns scientific results,
cohort definitions, and FSI/CSS formulas. This repository presents governed
results and preserves historical notebook evidence.

- Public is the foundational longitudinal WHOOP/Strava analysis and original
  hypothesis source, not merely a legacy model demo. Preserve its documented
  progression into the legal source-role design and refined longitudinal-plus-
  episodic Polar/Kubios evidence. See `docs/research_evolution.md`. Corrections
  qualify specific methods/claims, not the existence of the original research.
- Keep historical hypothesis/design lineage distinct from verified record-level
  derivation, current result authority, and the frozen exhibit's own snapshot.
  Do not backdate later findings or imply blanket revalidation of legal claims.

- Keep every file under `legal/` unchanged during public-notebook work.
- Never run legal reproduction, hash-update, or lock initialization targets as
  part of notebook maintenance. Existing integrity discrepancies must remain
  visible until a separately scoped reconciliation.
- Public notebooks use only the small, allowlisted aggregate bundle under
  `data/public/`. Do not add session rows, raw telemetry, routes, record IDs,
  legal/medical records, secrets, or local absolute paths to public outputs.
- Preserve the N-of-1 scope, endpoint-specific sample sizes, missingness,
  contrary results, and separate WHOOP overnight recovery from session HRV.
- FSI means Fractal Stability Index; CSS means Cohort Similarity Score.
  Preserve canonical identities, formulas, scopes, and experimental status.
- Notebook edits must preserve historical bytes in a local ignored backup
  before replacement. Never commit unless asked.
- Use focused synthetic tests and read-only source parity checks. Real
  inference, transformations, and report rendering run on the operator's M1 Max.
- Public notebook consumers must not call or modify the Evidence Observatory,
  DuckDB, deployment, production RAG, or the Evidence Registry.
